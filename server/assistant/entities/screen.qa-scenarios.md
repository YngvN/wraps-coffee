# QA scenarios: `screen` entity

Pulled into a cycle's own classification table (see `QA/templates/project/qa-test-plan-project.md`) whenever `server/assistant/entities/screen.ts` or its client-side wiring (`useAssistantFlow.ts`/`AssistantPanel.tsx`'s review-mount and destructive-delete branches, `reviewChangeRows.ts`'s `buildScreenChangeRows`) has changed since the last cycle that covered it. I.2/I.3 specifically test the entity's own scope boundary (global settings only, never pane layout/content) — the one place in this whole registry expansion where scope creep would be easy to miss, since `ScreenForm.tsx` is reused directly rather than a purpose-built mini-form. I.4 guards against the same confabulation pattern as `settings.qa-scenarios.md`'s H.2 — recurring on a second, independent entity is exactly what promoted it from a per-field fix to the standing confabulation rule (see `qa-test-plan-project.md`'s "Known app-level findings"), so treat any regression here as equally high-severity.

**As of 2026-08-04, this file has never been exercised in an actual QA cycle** — the entity shipped the same day this file was written.
