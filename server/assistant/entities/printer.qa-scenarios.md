# QA scenarios: `printer` entity

Pulled into a cycle's own classification table (see `QA/templates/project/qa-test-plan-project.md`) whenever `server/assistant/entities/printer.ts` or its client-side wiring (`useAssistantFlow.ts`, `AssistantPanel.tsx`'s `printer` branches, `PrinterMiniForm.tsx`, `buildPrinterChangeRows`) has changed since the last cycle that covered it. P.3 guards the entity's confabulation-risk fields (`host`, `systemName`) — treat a regression there as high-severity: a fabricated IP address would send receipts, with customer names and phone numbers, to whatever answers on it.

**First run, 2026-09-25 (the day it shipped), server steps only:** P.1–P.5 driven through the real `/assistant/intent` → `select-item` → `fill-fields`/`lookup` routes on the local provider, with a local Qwen 27B (llama.cpp) standing in for Ollama through a test shim. All five behaved as expected, including P.3 (`host` absent from the prompt under `'safe'`, draft rejected with `printerAddressRequired`). Not yet exercised: the review card and `PrinterMiniForm` in the real panel, and the actual save/delete on confirm — cover those in the next full cycle.
