# Deep-linkable admin views

- Several admin views (`ProductsView`, `ScreensView`, `EventsView`, `IntegrationsView`, `MessageBoardView`, `UsersView`, `DisplayManagerView`) support opening straight into a specific record instead of requiring clicks through the list, via query params they read with `useSearchParams()`: e.g. `?catalogueId=&categoryId=&productId=` (Products), `?screenId=&tab=` and `?new=1` (Screens), `?eventId=` (Events), `?integration=&newsSource=` (Integrations), `?boardId=&postId=` (Message board), `?userId=` (Users), `?pendingMachineId=&updateMachineId=` (Displays).
- **Settings' own sub-views are real routes, not query params** — `/admin/dashboard/settings/<section>` (`store`, `integrations`, `advanced`, `backup`, `developers`, `testing`) and `/admin/dashboard/settings/store/<subsection>` (`contact`, `appearance`), declared in `src/main.tsx` and read with `useParams()` in `SettingsView`/`StoreSettingsView`. They were query params (`?view=`/`?section=`) until 2026-08-15; the old shape still works via a one-shot redirect in each view, so don't reintroduce it for anything new. Because each sub-view is its own history entry, neither view needs `useBackLevel` anymore — the browser's own Back closes them.
- **Displays** (`DisplayManagerView`, the physical machines) is its own top-level route `/admin/dashboard/displays` and its own `NAV_ITEMS` entry, no longer a sub-view reached from Screens.
- The convention: read the target id(s) from `useSearchParams()`, resolve them once the underlying data actually exists (guard with a `consumedDeepLinkRef` when the data may not have loaded yet — synced hooks/async fetches often start out as a seed/empty/`null` value before the real snapshot arrives), open the right sub-state (a modal, an expanded accordion, a selected tab) via `queueMicrotask(() => setState(...))` (a plain synchronous `setState` inside an effect body trips this codebase's lint rule), then strip only the params that view itself consumed via `setSearchParams`. For a target that has no modal/form to open (e.g. a user row, a message board post), use `useScrollToAndHighlight` (`src/hooks/useScrollToAndHighlight.ts`) to scroll to and briefly highlight it instead.
- `useGlobalSearchIndex` (`src/features/admin/search/useGlobalSearchIndex.tsx`) is what turns every one of these deep links into a search result — it builds each entry's `url` to match exactly what the target view's own effect expects. When adding a new deep-linkable param to an existing view, or a new view that should support one, add/update the matching entry in `useGlobalSearchIndex` in the same change, the same way the `keep-in-sync` skill keeps new persistence in sync with `mirrorFile` — a view that's deep-linkable but not indexed here is a dead end nobody can actually search their way into.
